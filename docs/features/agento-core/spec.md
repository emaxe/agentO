# Спецификация: AgentO Core

## Контекст

AgentO — глобально устанавливаемый npm-пакет (`npm install -g agento`), который позволяет запускать различные CLI ИИ-агенты (Claude Code, OpenCode и другие) с предварительно настроенными API-провайдерами. Пользователь один раз настраивает доступы к нейронкам, создаёт именованные профили и затем быстро запускает любой агент с нужной конфигурацией.

Сервис управляет конфигами агентов: перед запуском патчит конфиг агента под выбранный профиль, после завершения — восстанавливает оригинал. Имеет TUI-интерфейс (Ink) и CLI-команды для скриптинга.

## Требования

**REQ-1.** Пользователь может добавлять, редактировать и удалять провайдеров API (OpenAI-compatible, Anthropic и другие типы) с полями: name, type, apiKey, baseUrl, models[].

**REQ-2.** Пользователь может создавать именованные профили — упорядоченный список пар (провайдер, модель). Профили универсальны и применимы к любому агенту.

**REQ-3.** Все настройки AgentO хранятся в `~/.agento/config.json` (JSON-формат).

**REQ-4.** AgentO поддерживает запуск агентов в двух режимах:
- **child**: агент запускается дочерним процессом, после завершения пользователь возвращается в AgentO, конфиг агента автоматически восстанавливается.
- **independent**: агент запускается независимым процессом (detached), AgentO завершается, конфиг остаётся изменённым до ручного восстановления.

**REQ-5.** Конфиг агента может создаваться/редактироваться на двух уровнях: **global** (глобальный конфиг агента) или **project** (проектный конфиг в `cwd` при запуске AgentO).

**REQ-6.** Перед патчингом конфига агента оригинал сохраняется в бэкап (`~/.agento/backups/<agent>/<scope>.bak.json`). В child-режиме восстановление происходит автоматически. В independent-режиме — по команде пользователя.

**REQ-7.** Каждый поддерживаемый агент имеет собственный адаптер, реализующий интерфейс `AgentAdapter`: чтение, генерация и запись конфига агента из профиля AgentO.

**REQ-8.** MVP поддерживает два агента: **Claude Code** и **OpenCode**.

**REQ-9.** Сценарий запуска агента через TUI: Профиль → Агент → (опционально: scope, mode) → Запуск.

**REQ-10.** TUI реализован на Ink (React-подобный синтаксис). Навигация: ↑↓ для выбора, Enter для входа, Esc/q для выхода на уровень выше.

**REQ-11.** TUI содержит разделы: Launch Agent, Providers (CRUD), Profiles (CRUD), Agents (статус конфигов, restore), Settings (defaultLaunchMode, defaultConfigScope).

**REQ-12.** CLI поддерживает команды: `launch`, `provider list/add/remove`, `profile list/add/remove`, `restore`, `agent status`. Без аргументов — запускает TUI.

**REQ-13.** При некорректном завершении AgentO во время работы агента в child-режиме (SIGTERM/SIGINT) — cleanup-хук восстанавливает конфиг агента.

**REQ-14.** Все CLI-команды возвращают exit-код 0 (успех) или 1 (ошибка).

**REQ-15.** Пакет разрабатывается с прицелом на macOS (приоритет), Linux и Windows.

## Ограничения

- API-ключи хранятся в plain-text в `~/.agento/config.json`. Шифрование keychain — вне скоупа MVP.
- Поддержка агентов ограничена MVP-списком: Claude Code и OpenCode. Остальные (Codex, Copilot CLI, Qwen CLI, Agent CLI) — будущие итерации.
- AgentO не управляет установкой самих агентов — предполагается, что они уже установлены.
- Фолбэки между моделями профиля (при недоступности первой) — вне скоупа MVP. Используется первая пара (провайдер, модель) из списка профиля.
- Drag-and-drop для переупорядочивания моделей в профиле — вне скоупа MVP, только up/down стрелки.
- Нет облачной синхронизации конфигов — только локальное хранение.

## Кодстайл и конвенции

- **Язык:** TypeScript (strict mode)
- **Runtime:** Node.js ≥ 18
- **Пакетный менеджер:** npm
- **Сборка:** tsup или tsc
- **TUI:** Ink 4.x + React 18
- **Валидация схем:** Zod
- **Линтер:** ESLint + Prettier
- **Тесты:** Vitest
- **Именование файлов:** kebab-case для файлов и папок, PascalCase для React-компонентов (`.tsx`)
- **Импорты:** ESM (`.js` расширения в import-путях для совместимости с Node ESM)
- **Barrel-файлы:** `index.ts` в каждом модуле для экспорта публичного API

## Переиспользуемые решения

Проект создаётся с нуля — существующего кода нет.

**Ключевые внешние зависимости:**
- `ink` + `react` — TUI
- `zod` — валидация конфигов
- `commander` или `yargs` — CLI-парсинг аргументов
- `chalk` или `ansis` — цветной вывод в CLI-режиме
- `@clack/prompts` — опционально для CLI-интерактивности вне TUI

## Критерии приёмки

- [ ] `npm install -g agento` устанавливает пакет, команда `agento` доступна глобально
- [ ] `agento` без аргументов открывает TUI с главным меню
- [ ] В TUI можно добавить провайдера с apiKey, baseUrl, списком моделей
- [ ] В TUI можно создать профиль с парами (провайдер, модель)
- [ ] `agento launch --profile <name> --agent claude-code` запускает Claude Code с конфигом из профиля
- [ ] `agento launch --profile <name> --agent opencode` запускает OpenCode с конфигом из профиля
- [ ] В child-режиме после выхода из агента конфиг агента восстанавливается автоматически
- [ ] В independent-режиме `agento restore --agent claude-code --scope global` восстанавливает конфиг
- [ ] При SIGTERM/SIGINT во время child-режима конфиг агента восстанавливается
- [ ] При вызове `restore` без существующего бэкапа — понятное сообщение об ошибке и exit-код 1
- [ ] Все CLI-команды возвращают exit-код 0 или 1
- [ ] Конфиг AgentO персистится между сессиями в `~/.agento/config.json`
- [ ] TUI-навигация работает: ↑↓, Enter, Esc/q
